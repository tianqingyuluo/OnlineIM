# v1 - 消息编辑（edit）

## 背景

用户发送文本消息后发现有误，希望就地编辑而非撤回重发。当前消息文档无 `edited` 标记与编辑历史，无法编辑。本任务为文本消息增加编辑能力（带标记，可选保留编辑历史）。

## 用户旅程

> 原 PRD 此节为待头脑风暴的占位符。2026-10-22 按 tianqingyuluo 给出的 Step 7 要求（只能编辑自己的文本消息、时间窗与撤回一致、记录 edited/edited_at、实时推送给会话全部成员、桌面与手机显示“已编辑”、最后一条被编辑时更新会话预览、不能编辑非文本 / 已撤回 / 别人的消息）补全如下，作为 v1 范围。对头脑风暴各方向的结论：
> - 触发：右键（手机长按）菜单“编辑”；只支持文本（text）。
> - 时间窗：与撤回一致，默认 2 分钟（`im.message.edit-window-seconds`，默认取撤回时间窗）。
> - 历史：服务端保留原文与每个旧版本（最多 20 个，原文始终保留），**本期不对外提供“查看原内容”**。
> - 通知：编辑后所有会话成员实时收到 `MESSAGE_EDITED`，气泡显示“已编辑”；不产生新消息、不加未读、不改排序。
> - 已读回执：编辑不影响送达 / 已读状态。
> - 引用：回复保留引用时的快照，原消息被编辑后引用显示“原消息已编辑”（沿用 message-reply 已有的 `edited` 状态）。
> - 群 @：编辑可改变 @ 的成员，不再被 @ 的人“有人@我”消失，新被 @ 的人出现。

1. 用户 A 在私聊或群里发出一条文本消息，发现写错了。
2. A 在 2 分钟内右键（手机长按）这条消息，菜单里有“编辑”；别人的消息、图片 / 文件 / 语音 / 表情 / 聊天记录、已撤回的消息、超过 2 分钟的消息都没有“编辑”。
3. A 点“编辑”：原文放进输入框（输入框里原来没发出的草稿先暂存），上方出现“编辑消息”条显示原文，发送按钮变成“保存”。群聊中原来 @ 的成员保留（只要文本里还有对应的 `@名字`），也可以用 @ 选择器加人。
4. A 修改后回车或点“保存”：气泡立刻变成新内容并在右下角显示“已编辑”（悬停显示编辑时间），输入框恢复原来的草稿。内容没变直接退出，不产生新版本。Esc 或 ✕ 取消编辑，同样恢复草稿。
5. 会话里的其他成员（以及 A 的其他标签页）实时看到这条消息变成新内容并显示“已编辑”；不会多出一条消息，未读数不变。
6. 如果这条是会话的最后一条消息，所有成员会话列表里的预览随之变成新内容（不改时间、不重新排序）。
7. 引用了这条消息的回复，引用块显示“原消息已编辑”，引用内容仍是引用时的原文。
8. 群聊里编辑改变了 @：不再被 @ 的成员 `[有人@我]` 消失，新被 @ 的成员出现 `[有人@我]`。
9. 被拒绝的情况：编辑别人的消息、非文本、已撤回、超过时间窗、内容为空或过长、已不是好友 / 已退群，服务端拒绝并提示原因（例如“消息发送已超过2分钟，无法编辑”），消息不变；编辑过程中超过时间窗或消息被撤回，提示后退出编辑态。
10. 刷新页面或在其他设备上打开，看到的都是编辑后的内容和“已编辑”标记。

## 需求

- 文本消息支持编辑，新增 `edited`/`editedAt` 标记；服务端保留原文与旧版本（最多 20 个），不对外提供。
- 编辑时间窗与撤回一致（默认 2 分钟，可配置）。
- 编辑后广播 `MESSAGE_EDITED` 事件（REST `PUT /api/v1/messages/{id}` 或 WS `EDIT_MESSAGE_REQUEST`），对端更新展示。
- 客户端：编辑入口、编辑态展示、"已编辑"标记（本期不提供查看历史）。

## e2e 测试场景

> 原为占位符，按上方用户旅程补写（2026-10-22）。自动化脚本：`test/e2e-test.mjs --edit`（== 17 节，可单独运行）与 `test/ui-step7.mjs`（真实浏览器，桌面 + 手机）。

- **E1 REST 编辑（旅程 1、4、5）**：`PUT /api/v1/messages/{id}` 编辑自己的私聊文本 -> 200，内容去首尾空白，`edited=true`、`edited_at`、`content_revision=2`，`message_id` / `seq_id` / 发送时间不变，响应不含原文与编辑历史；对方与编辑者自己的连接都收到 `MESSAGE_EDITED`；不产生新消息帧；Mongo 中 `editHistory[0]` 为原文；历史接口返回新内容与标记。
- **E2 WS 编辑与预览（旅程 5、6）**：`EDIT_MESSAGE_REQUEST` 编辑最后一条 -> 双方收到推送、无 ERROR；双方会话预览变为新内容，`last_message` 仍指向该消息，未读数不变；编辑的不是最后一条时预览不变。
- **E3 版本（旅程 4）**：内容没变 -> 200 原样返回、版本不变、不推送；再次编辑 -> `content_revision=3`，`editHistory` 依次保存原文与第二版；3 个并发编辑 -> 成功的各占一个版本，其余 409 `EDIT_CONFLICT`。
- **E4 引用联动（旅程 7）**：引用了被编辑消息的回复 `reply_to.state=edited`，`preview_text` 仍为引用时的原文。
- **E5 拒绝（旅程 2、9）**：别人的消息 403 `NOT_MESSAGE_SENDER`（REST 与 WS ERROR 帧，回带 `client_message_id`）；图片 400 `EDIT_NOT_SUPPORTED`；已撤回 409 `MESSAGE_ALREADY_RECALLED`；空内容 / 缺 content / 超过 5000 字 400 `EDIT_CONTENT_INVALID`；不存在 404；未登录 401；超过 2 分钟（REST 与 WS）400 `EDIT_WINDOW_EXPIRED` 且数据不变；删好友后 403 `NOT_CONVERSATION_MEMBER`；退群后 403。
- **E6 群 @（旅程 8）**：把 @E2 改成 @E3（混入非成员与自己）-> `at_users=[E3]`；推送帧 E3 `at_me=true`、其他人 false；E2 的 `[有人@我]` 消失、E3 出现；群预览更新、未读不增加；不带 `at_users` 编辑保持原 @；`editHistory[0]` 保留原文与原 @ 列表；群成员编辑别人的群消息 403。
- **U1 桌面 UI（旅程 2~7、9、10）**：菜单“编辑”只出现在自己 2 分钟内的文本上；编辑条、原文入框、“保存”按钮、草稿暂存与恢复；保存后双方气泡实时更新并显示“已编辑”（悬停显示时间）；引用块实时显示“原消息已编辑”；最后一条被编辑后双方列表预览更新；Esc / ✕ 取消；编辑中超过时间窗提示并退出；刷新后仍显示“已编辑”。
- **U2 手机 UI（旅程 2、4、5、6）**：别人编辑群消息后实时更新、“已编辑”、不再高亮 @我；长按别人的消息无“编辑”、自己的有；编辑条不超出屏幕；保存后显示“已编辑”；桌面端与手机列表的群预览同步更新。
