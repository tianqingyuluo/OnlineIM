# v1 - 多端登录策略

## 背景

当前 deviceID 体系支持多设备，但未见"单设备挤下线 / 多端共存"的策略。用户用同一账号在新设备登录，旧设备是否被踢、是否互斥、是否多端同时在线，行为未定义。本任务明确并实现多端登录策略。

## 用户旅程

> 结论（按本次任务说明落地，不再保留占位）：设备类型分为网页 `web`、桌面 `desktop`、手机 `phone`。同一类型同时只保留一个会话，新登录挤掉旧的；不同类型可以同时在线。被挤下线的一端收到 WebSocket 通知后退出登录，并看到明确文案；该会话的 token 立即失效。同时在线的设备之间同步消息和已读，自己在一台设备发出的消息会出现在另一台。提供已登录设备列表，可以远程登出其他设备。

1. 用户在网页登录。浏览器是手机或平板时设备类型为 `phone`，否则为 `web`；桌面壳可以显式声明 `desktop`。同一浏览器会记住自己的 `device_id`，刷新不会被当成一台新设备。
2. 用户再用另一台网页（或另一个浏览器）登录同一账号。先登录的网页收到“您的账号已在其他网页端登录，当前设备已下线”，回到登录页，不能继续收发消息；原来的 token 再请求接口会被拒绝。
3. 手机（或桌面）仍然在线。网页和手机可以同时收消息。
4. 用户在网页发出一条消息。手机上的同一会话出现这条消息，未读数不增加。手机上发出的消息同样出现在网页。
5. 用户在网页把会话读完。手机上该会话的未读角标清掉。对方的已读状态不受影响。
6. 用户在网页打开“登录设备”，看到网页和手机。当前设备没有登出按钮。点手机的“登出”后，手机收到“该设备已被远程登出”并回到登录页；网页自己仍保持登录。
7. 用户在当前设备点“退出”，只结束这一台的登录，其他类型的设备不受影响。

## 需求

- 定义并实现多端登录策略：`web` / `desktop` / `phone` 每种一个会话，同类型新登录挤掉旧会话，跨类型共存。
- 被挤下线时通过 `SESSION_KICKED` 通知旧端，展示明确文案，停止重连并清除本地登录态；旧 token 进入黑名单。
- 消息、撤回、编辑和已读回执投递到该用户全部在线设备；自己发出的消息同步到其他设备。
- 设备列表查询与远程登出。
- 客户端：被挤下线提示、登录设备列表。

## e2e 测试场景

本环境没有可启动的 Docker 中间件，以下场景留给仓库所有者在真实栈上验收（不在本变更里新增浏览器 e2e）：

1. 两个网页登录同一账号：后登录的成功，先登录的立刻看到挤下线文案并回到登录页；用旧 token 调接口返回 401。（旅程 2）
2. 网页与手机同时在线：互发消息，对端和自己的另一台设备都能看到；未读只加在“别人发给我、且我没在看”的设备上。（旅程 3、4）
3. 在网页读完会话：手机未读变为 0；对方看到的已读位置前进。（旅程 5）
4. 设备列表含当前设备和其他设备；远程登出手机后，手机下线，网页仍可用。（旅程 6）
5. 当前设备退出后，另一种类型的设备仍在线。（旅程 7）

## 测试范围

- 后端：`DeviceTypesTest`（类型归一、挤下线文案、设备标识）、`DeviceSessionServiceTest`（同类型挤下线并作废 token、跨类型共存、远程登出、断线后仍算已登录）、`DeviceSessionControllerTest`、`LocalSessionRegistryTest`（同一用户多连接、同设备替换不误伤其他设备）、`PrivateMessageReceiverTest`（接收方与发送方的每台设备都收到）、`ReceiptServiceImplTest`（已读回执也发给阅读者本人）。
- 前端 vitest：`utils/device-session`（设备类型与稳定 device id）、`websocket.service`（`SESSION_KICKED` 后退出且不重连）、`history`（其他设备发出的消息出现在当前会话、自己的已读同步不清对方已读）、`conversation-live`（另一台设备已读后未读清零）、设备列表面板。
- 部署验收：见上方 e2e。本变更跑 `mvn test` 与 `vitest`。

## 验收标准

- [x] 多端登录策略明确生效：每种设备类型一个会话，同类型新登录挤掉旧会话
- [x] 挤下线旧端收到 `SESSION_KICKED` 并退出，token 失效
- [x] 多端在线时消息与已读一致，自己发出的消息出现在其他设备
- [x] 协议字段登记到 v1 协议清单
- [x] 设备列表与远程登出
- [x] 后端单元测试与前端 vitest 通过
