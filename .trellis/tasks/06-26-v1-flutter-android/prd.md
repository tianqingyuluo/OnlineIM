# v1 - Flutter 安卓客户端

## 背景

当前前端仅有 Vue Web 端。本任务以 Flutter 独立工程实现安卓客户端，三端共用同一套 HTTP + WS 接口。属 [[v1-tauri-flutter-clients]] 父任务的孙任务，与 [[v1-tauri-desktop]] 并列。Flutter 工程与 Vue 工程相互独立，不复用前端源码，仅复用后端协议。

## 已敲定的产品决策

- **目标市场**：先国内市场。设备无 GMS，FCM 不可用。
- **推送策略**：v1 不做系统厂商推送。应用前台/后台用前台服务保活 WS 长连接实时收消息；应用被杀则收不到实时提醒，下次上线由 [[v1-offline-push]] 补齐漏收。系统厂商推送延后至 v1.x。
- **minSdk**：24（Android 7.0），targetSdk 最新稳定版。覆盖国内 95%+ 设备。
- **分发与更新**：自分发 APK（官网/下载页提供安装包），需用户允许"未知来源安装"。不上架应用商店（v1.x 再考虑）。更新靠用户重新下载安装。
- **三端功能完全一致**：v1 安卓端功能集与 Web 端完全对齐，不裁剪（含 WebRTC/E2EE/搜索/转发等全部能力的 Flutter 实现）。
- **iOS 不在 v1 范围**。

## 用户旅程

> 核心会话旅程与 Web 端一致，依赖各协议任务冻结后回填细节；此处记录安卓端特有旅程与框架。

### 安卓端特有旅程

1. **安装**：用户下载自分发 APK，允许"未知来源安装"并安装。
2. **登录**：账号密码登录，token 持久化（Android Keystore），重启免登录。
3. **主会话旅程**：与 Web 端一致 —— 收发消息（文本/图片/文件/语音）、已读回执、消息操作（回复/编辑/撤回/转发/@提及/搜索）、在线状态、多端登录、会话列表。具体协议行为依赖对应协议任务冻结。
4. **前台服务保活**：应用切后台时前台服务保活 WS 长连接，持续在线收消息；前台服务带持久通知（API 26+ 要求）。
5. **应用被杀**：系统杀掉应用后 WS 断开，实时消息收不到；用户下次启动应用上线后由 [[v1-offline-push]] 补齐漏收消息与未读数。
6. **通知权限**：Android 13+（API 33）运行时申请通知权限；权限授予后消息到来时展示系统通知。
7. **WebRTC 通话**：发起/接听时运行时申请麦克风/摄像头权限；1v1 视频通话全流程；通话最小化、静音、摄像头切换。
8. **E2EE 私聊**：与 Web 端一致；私钥存储于 Android Keystore（依赖 [[v1-e2ee]] 任务冻结）。
9. **文件/图片**：选择相册/文件时申请存储/相册权限（scoped storage）；发送图片含缩略图。
10. **退出**：登出清理会话与连接，token 清除。

### 依赖协议任务冻结的开放项

以下旅程细节待对应协议任务冻结后回填，当前不臆造：
- 心跳/断连重连：移动端切后台、网络切换、省电模式下的重连策略（[[v1-ws-heartbeat-reconnect]]）
- 多端登录策略：安卓端与 Web/桌面端的共存/互斥口径（[[v1-multi-device-login]]）
- 离线推送兜底：上线未读补齐行为（[[v1-offline-push]]）
- presence 在线态粒度与展示（[[v1-user-presence]]）
- WebRTC 信令流程、被叫离线未接来电、多端响铃（[[v1-webrtc-video-call]]）
- E2EE 密钥分发与三端存储（[[v1-e2ee]]）
- ACK/已读回执协议字段（[[v1-message-ack-read]]）

## 需求

- Flutter 独立工程，不复用 Vue 源码，仅复用后端 HTTP + WS 协议。
- 目标平台：Android，minSdk 24，targetSdk 最新稳定版；iOS 不在 v1 范围。
- 前台服务保活 WS 长连接，前台服务带持久通知。
- 不做系统厂商推送；离线漏收靠上线补齐（与 [[v1-offline-push]] 协同）。
- 运行时权限：通知（Android 13+）、麦克风/摄像头（WebRTC）、存储/相册（文件图片）。
- 本地缓存用 SQLite 系方案（具体选型见 design.md），与 Web 端 idb 对应消息/会话缓存结构。
- token 持久化用 Android Keystore（`flutter_secure_storage`），不用明文 SharedPreferences。
- 自分发 APK，产出签名 Release 包。
- 三端协议实现一致，WS 消息类型与行为与 Web 端对齐。
- 依赖协议的细节（E2EE 密钥存储、WebRTC 信令、推送通道、多端登录）列为开放项，待对应任务冻结后回填。
