# v1 - 群 @全员 与 群公告已读名单

## 背景

群聊需要 @全员（群主/管理员一次提醒全体）和群公告的已读确认。@单人已经走 `at_users` + 会话 `pendingMentions`（`[有人@我]`）；公告已有 CRUD 和置顶，但没有“谁看过”。本任务在这两套现成机制上补齐，不另起一套提及或已读模型。

## 用户旅程

> 结论（按本次实现说明落地，2026-10-21）：@所有人只给群主/管理员，服务端强制；高亮复用现有 @我；公告要成员主动确认，未确认前聊天里的公告条和弹层一直在，群主/管理员看已读/未读人数和名单，变更走 WebSocket 实时更新。本期不做频次限制。

1. 群主或管理员在群聊输入 `@`（或点输入框旁的 @）时，候选列表第一项是“所有人”。普通成员的候选列表里没有这一项。
2. 选中后正文插入 `@所有人 `。删掉这段文字再发送，就不会 @全员。可以同时 @ 具体成员。
3. 服务端只接受群主/管理员的 `@所有人`（`at_users` 含保留值 `all`）。普通成员即使伪造请求，`all` 也会被丢掉，其他合法的 @单人仍然保留，整条消息照常发出。
4. 除发送者以外的每一位当前成员，会话列表都出现红色 `[@所有人]`（这就是 @全员版的“有人@我”）。若另外还有单独 @ 到自己、且还没读的消息，同时显示 `[有人@我]`。点进会话并读到这些消息后，标记按现有已读游标清掉。
5. 消息气泡里的 `@所有人` 高亮；被 @ 到的人（含 @全员的接收者）用更醒目的样式。
6. 群里有自己还没确认的公告时，聊天窗口顶部一直显示公告条。点开是公告弹层，内容还在，直到点“我知道了”。关掉弹层但不确认，公告条不消失。有多条未读时，置顶优先，否则最新的一条。
7. 确认后该公告对自己不再出现；群主/管理员看到已读人数、未读人数，以及已读/未读成员名单。有人确认时，正在看的群主/管理员实时看到人数和名单变化，不用刷新。
8. 新公告或正文/标题被修改后，除操作者本人外大家都要重新确认，在线成员马上看到公告条。只改置顶不重置已读。删除后公告条消失。
9. 发布者/修改者本人视为已读，不会被自己刚发的公告挡住。非成员不能确认，也不能看名单。

## 需求

- @所有人复用 `at_users`，保留值 `all`（与前端 `MENTION_ALL_ID` 一致）。不把 `all` 展开成成员 ID 列表，因此不受“最多 @ 50 人”的限制，也不随之后退群/入群改写历史消息。
- 只有群主或管理员（`group_members.role <> 0`，或 `groups.owner_id`）可以留下 `all`；普通成员的 `all` 静默丢弃。WebSocket 与 HTTP 发送、以及编辑消息时重新清洗，规则相同。
- 会话记录：`all` 给除发送者外的每个当前成员写一条 `pendingMentions`，并带 `atAll=true`。会话接口增加 `at_all` / `at_all_count` / `at_all_message_id`。`at_me` 对 @全员同样为 true，旧客户端仍会显示 `[有人@我]`。
- 实时帧 `GROUP_MESSAGE_RESPONSE`、`MESSAGE_EDITED` 增加顶层 `at_all`。`at_me` 在 @全员时对接收者为 true。
- 群公告已读存在 MySQL `group_announcement_reads`（公告 + 用户唯一）。成员 `POST .../read` 确认，重复确认不改首次已读时间。
- 列表和详情对当前用户带 `read_by_me`。群主/管理员额外带 `read_count`、`unread_count`（只统计当前在群成员）。`GET .../reads` 仅群主/管理员，返回已读与未读名单。
- 发布、修改标题或正文、删除，经 Redis Stream 推 `GROUP_ANNOUNCEMENT`；有人新确认推 `GROUP_ANNOUNCEMENT_READ`（群主/管理员能看到人数，普通成员只收到与自己有关的确认）。
- 已有库启动时幂等建表；`onlineIM.sql` 同步收录该表。

## e2e 测试场景

与上面的旅程对应。本仓库自动化覆盖单元/组件层；下面是主人在真实 Docker 栈上的手工路径（也是部署验收时应走的步骤）：

1. 普通成员在群里输入 `@`：候选没有“所有人”。用接口给 `at_users: ["all"]` 发一条文本，落库的 `at_users` 不含 `all`，其他成员会话列表不出现 `[@所有人]`。（旅程 1、3）
2. 群主或管理员选“所有人”发送 `@所有人 开会`。每个其他成员的会话列表出现红色 `[@所有人]`，气泡里 `@所有人` 高亮。发送者自己的列表没有这条提醒。（旅程 2、4、5）
3. 再单独 @ 某一位成员。该成员同时看到 `[@所有人]` 和 `[有人@我]`；只被 @全员的成员只看到 `[@所有人]`。读到最新后两处标记都消失。（旅程 4）
4. 管理员发布公告。其他在线成员聊天顶部出现公告条，点开弹层，未点“我知道了”就关闭时公告条仍在。点“我知道了”后公告条消失。（旅程 6、7）
5. 管理员打开该公告，看到已读/未读人数和名单；成员确认时人数和名单实时变化，无需刷新。（旅程 7）
6. 修改公告标题或正文后，已确认的成员再次看到公告条；只改置顶不会。删除公告后公告条消失。（旅程 8）
7. 非成员调用确认或已读名单接口得到 403；普通成员调用名单接口得到 403。（旅程 9）

## 测试范围

- 后端单元：`MentionUtil`（权限下保留/丢弃 `all`、不占 50 人额度）、`GroupMessageSender`（管理员保留 `all`，成员丢弃）、`MessageEditService`（编辑时按当前身份重新清洗并 `replaceMentions`）、`ConversationRecordServiceIntegrationTest`（@全员给除发送者外的每个成员打标，编辑后按新列表重写）、`GroupAnnouncementReadServiceTest`（确认幂等、名单权限、改内容清空已读、非成员拒绝）、`GroupAnnouncementReceiverTest`（帧类型与非管理员不带人数）。
- 前端 vitest：`mention` 工具（候选首位“所有人”、`@所有人` 高亮）、会话列表 `[@所有人]` / `[有人@我]`、`conversation-live` 实时打标、公告条选择与 WebSocket 帧归并、公告条组件确认前不消失。
- 手工：见上方 e2e 场景。Tauri/Flutter 本期只登记协议，不改客户端。

## 验收标准

- [x] 仅群主/管理员能 @所有人；普通成员的入口和伪造请求都不会生效
- [x] 其他成员会话列表出现 `[@所有人]`，并与原有 `[有人@我]` 共存；读后清除
- [x] 复用 `at_users`（保留值 `all`）和 `pendingMentions`，不新造提及通道
- [x] 成员确认公告前，公告条/弹层保持；确认后消失
- [x] 群主/管理员看到已读、未读人数和名单；确认与发布/修改/删除经 WebSocket 实时更新
- [x] 协议字段登记到 `docs/ws-protocol-registry.md`
- [x] 后端 `mvn test` 与前端 vitest 通过

## 依赖

- 依赖 [[v1-mention-at]]（`at_users`、`pendingMentions`、`[有人@我]`）和 [[v1-message-ack-read]]（已读游标清掉 @ 标记）。公告已读不复用消息 `readSeq`，因为公告不是一条聊天消息。
