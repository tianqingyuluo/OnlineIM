# v1 - @提及功能（at）

## 背景

群聊中需要 @ 某人以引起注意并触发专门通知（免打扰穿透/红点强提醒）。当前消息体无 `mentionUserIds` 字段，无法区分普通消息与 @ 消息，也无法对被 @ 者做差异化提示。

## 用户旅程

> 原 PRD 此节为待头脑风暴的占位符。2026-10-21 按 tianqingyuluo 给出的 Step 5 要求（@单人；@所有人 是后续单独一步）补全如下，作为 v1 范围。@所有人、穿透免打扰的系统通知、单独的“@我的消息”列表页、编辑后的 mention 联动不在本次范围（消息编辑尚未实现）。

1. 群成员（含普通成员）在群聊输入框输入 `@`（手机上也可点输入框右下角的 `@` 按钮），弹出当前群成员列表（不含自己），显示公开名（群昵称 > 昵称 > 用户名），有好友备注的同时显示备注。
2. 继续输入文字按群昵称 / 昵称 / 好友备注 / 用户名过滤（不区分大小写，前缀命中排前）；`↑/↓` 移动、`Enter`/`Tab` 选中、`Esc` 关闭，也可鼠标点击或手指点按选中。选中后输入框插入 `@公开名 `。
3. 发送时客户端只提交文本中仍保留 `@公开名` 的成员（删掉文字即取消提及），作为结构化 `at_users`（WS 与 HTTP 发送都支持）。服务端只对文本消息生效，去重、去空、去掉发送者自己、只保留**当前**群成员（非成员 / 已退群 / 不存在的 ID / `all` 静默剔除，不报错），最多 50 个；没有剩余时不存 `at_users`。私聊忽略 `at_users`。
4. 被 @ 的在线成员收到的 `GROUP_MESSAGE_RESPONSE` 帧带顶层 `at_me=true`（其他成员 `false`），消息体 `at_users` 为清洗后的列表；历史 / 同步接口同样返回 `at_users`。
5. 被 @ 的成员（在线或离线）会话记录增加一条待读 @，会话接口返回 `at_me=true`、`at_me_count`、`at_me_message_id`（最早一条未读 @）。会话列表在预览前显示红色 `[有人@我]`；未被 @ 的成员和发送者没有。
6. 消息气泡中属于 `at_users` 的 `@名字` 高亮（蓝色）；@我 的用琥珀色底色强调。
7. 被 @ 的成员打开群聊、读到该消息（已读游标越过它）后标记消失；只读到更早的消息时只剩之后的 @。发送者撤回该消息后，被 @ 者的标记同时移除。
8. @所有人：本次不实现。预留：前端 `MENTION_ALL_ID='all'`，服务端 `MentionUtil` 目前把 `all` 当作无效 ID 剔除；后续步骤在这两处加入权限判断与全员展开即可。

## 需求

- 消息（群聊为主）支持 `mentionUserIds[]` 字段（协议名统一为 `at_users`，HTTP 兼容旧名 `atUserIds`）。
- 发送时服务端校验被 @ 者为当前群成员。
- 接收侧对被 @ 者做差异化通知（具体强度以结论为准），并在消息流高亮 @ 标记。
- 客户端：`@` 触发成员选择器、提及高亮渲染、"@我"入口（若采用）。
