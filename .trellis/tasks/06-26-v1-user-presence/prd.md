# v1 - 用户在线状态（presence）

## 背景

IM 社交属性需要看到对方"在线/离线"状态。当前服务端有 `LocalSessionRegistry` 维护本地连接，但未对外暴露 presence，也未在多实例间聚合。用户看不到好友/群成员的在线态。本任务实现 presence 体系：多实例聚合 + 变更推送 + 客户端展示。

## 用户旅程

> 原 PRD 此节为待头脑风暴的占位符。2026-10-21 按 tianqingyuluo 给出的预期结果补全，作为 v1 范围。对头脑风暴各方向的结论：
> - 状态粒度：只有在线 / 离线两态，不做离开、勿扰。离线时带上次在线时间（`last_seen_at`）。
> - “离开”不单列：心跳超时或连接断开后即为离线，上次在线时间取最后一条连接结束的时刻。
> - 谁能看见：互为好友（双方 `user_friends.status = 1`），或仍在同一个未解散群里的成员。陌生人看不见。拉黑或删除好友后不再通过好友关系可见；若两人仍在同一群，群成员列表仍能看到（群成员本来就能看到彼此）。
> - 隐私：用户可在个人资料里打开“隐藏在线状态”。打开后，好友和群成员看到的与离线相同（`offline`，且不给上次在线时间），也不再收到该用户的上线推送。自己查自己始终看到真实状态。
> - 推送：不单独做订阅/退订帧。关系即订阅——WebSocket 连着的时候，服务端把变更推给有权看见的人；连接断开即不再接收。初始状态用 REST 批量查询。
> - 多端：同一用户的多个标签页 / 设备各自一条连接。任一连接仍在就显示在线；最后一条连接关闭（或心跳超时被清理）才变为离线。
> - 多实例：连接登记在 Redis，任一实例都能算出这个人是否在线。心跳超时沿用现有 `websocket.heartbeat.timeout`（默认 90 秒）；实例崩溃时靠连接键过期，由定时清理补一次离线推送。
> - 展示位置：好友列表、私聊标题栏、群成员列表（含群资料里的成员网格）；群聊标题栏显示“N 人在线”。桌面和手机同一套数据。

1. 用户 A 登录并连上 WebSocket。A 的好友 B、以及和 A 在同一群的成员，好友列表 / 私聊标题 / 群成员列表里看到 A“在线”，群聊标题的在线人数加一。
2. A 再开一个标签页或另一台设备。B 看到的仍然是“在线”，不会闪成离线。A 关掉其中一个，只要还有连接，B 看到的还是“在线”。
3. A 关掉最后一个连接（或停止心跳直到服务端判定超时）。B 看到 A 变为“离线 · 刚刚”（之后随时间变成“N 分钟前”等），群在线人数减一。
4. B 刚打开应用、还没收到推送时，好友列表、当前私聊标题和群成员列表用 `GET /api/v1/presence?user_ids=` 拉一次初始状态，随后以 WebSocket `PRESENCE_UPDATE` 更新。
5. 陌生人 C 不能查出 A 的在线态（结果 `visible: false`，没有状态和上次在线时间）。A 拉黑 B 之后，B 不再因为好友关系看到 A；若两人仍在同一群，群成员列表里仍能看到。
6. A 在个人资料（桌面和手机的编辑资料）打开“隐藏在线状态”。正在看 A 的人收到一次离线（没有上次在线时间）。A 此时其实还连着，但别人一直看到离线。A 关掉隐藏后，别人立刻看到真实状态。
7. 手机上同样：好友列表、聊天标题、群成员列表和隐藏开关都可用。

## 需求

- presence 存在 Redis，按连接聚合，多实例共用；在线 = 至少还有一条未过期的连接。
- 最后一条连接关闭或心跳超时后变为离线，并记录 `last_seen_at`。
- 变更经现有 Redis Stream 推送 `PRESENCE_UPDATE`（只推给有权看见的在线用户）。
- 隐私：仅互为好友或同群成员可见；可隐藏在线状态。
- 接口：批量查询初始状态、读取/更新隐藏开关。不另设订阅帧。
- 客户端：好友列表、私聊标题、群成员列表、群聊标题在线人数；桌面和手机。

## e2e 测试场景

> 原为占位符，按上方用户旅程补写（2026-10-21）。自动化以服务端生命周期测试 `PresenceServiceTest` 覆盖旅程 1~6 的状态机（多连接、最后一条才离线、心跳过期清理、隐藏、好友/同群/陌生人/拉黑），前端 vitest 覆盖展示文案与实时写入。不依赖 Docker 全栈；手工验证见 PR 说明。

- **P1 上线（旅程 1）**：第一条连接登记后状态变为 online，并向好友 / 同群成员推送 `PRESENCE_UPDATE`（`status=online`，`last_seen_at=null`）。
- **P2 多端（旅程 2）**：第二条连接不再推送；关掉其中一条仍为 online；关掉最后一条才变为 offline，并带 `last_seen_at`。
- **P3 心跳超时（旅程 3）**：连接键过期后，清理任务只在“从在线变成离线”时推送一次 offline。心跳续期后不会被清掉。
- **P4 初始查询（旅程 4、5）**：`GET /api/v1/presence?user_ids=` 对好友和同群成员返回状态；对自己返回真实状态；对陌生人 `visible=false` 且不带状态。未登录 401；空列表或超过 100 个 400。
- **P5 隐私（旅程 5、6）**：隐藏后查询结果为 offline 且 `last_seen_at=null`，上线不推送；关闭隐藏后按真实状态再推一次。单向拉黑不算好友。
- **U1 文案**：在线显示“在线”；离线无时间显示“离线”；有上次在线时间显示“刚刚 / N 分钟前 / N 小时前 / 昨天 / 日期”。
- **U2 实时**：收到 `PRESENCE_UPDATE` 后，好友列表、私聊标题、群成员列表和群在线人数使用同一份状态。

## 测试范围

> 原为占位符，按上方用户旅程补写（2026-10-21）。

- **后端单元**：`InMemoryPresenceConnectionStore` + `PresenceServiceTest`（多连接聚合、最后一条离线、重复下线不重复推送、心跳续期与过期清理、隐藏开关、查询权限与批量上限）；`PresenceAudienceServiceTest`（互为好友、单向关系不算、同群、已退出/已解散不算）；`PresenceControllerTest`（路由、未登录 401、参数原样交给服务）；`PresenceUpdateReceiverTest`（推到该用户本节点的全部连接）；`LocalSessionRegistryTest` 补充同一用户多条连接，关掉一条不会拆掉另一条。
- **前端单元（vitest）**：`presence` 文案；`presence` store（批量查询分片、隐藏开关、推送写入）；`PresenceLabel`；WebSocket 收到 `PRESENCE_UPDATE` 写入 store。
- **回归**：后端 `mvn test`，前端 `vitest run`。

## 验收标准

- [x] presence 多实例聚合正确（Redis 连接集合；离线仅发生在最后一条连接结束）
- [x] 有权看见的人实时收到状态变更
- [x] 隐私策略生效（好友 / 同群可见，可隐藏在线状态）
- [x] 协议字段登记到 v1 协议清单
- [x] 单元 / UI 测试全绿（见“测试范围”）。本环境无 Docker：`./mvnw test` 里既有的 Testcontainers 用例仍会失败；本任务新增的 Redis Lua 集成测试在无 Docker 时跳过，其余 presence 单测与前端 vitest 已通过。
