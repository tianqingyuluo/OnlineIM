# v1 - Tauri 桌面客户端 + Flutter 安卓客户端（父任务）

## 任务定位

本任务为 **parent 任务**，持有三端共享需求、任务地图、跨孙任务集成验收口径与最终集成评审；**本身不直接承担实现**。两个可独立验证的交付物下沉为孙任务：

- [[v1-tauri-desktop]] — Tauri 桌面端（复用 Vue 工程封装）
- [[v1-flutter-android]] — Flutter 安卓客户端（独立工程）

端到端用户旅程、技术设计、执行清单在各自孙任务内编写；本 PRD 只记录三端共享口径、依赖边界与父级验收标准。

## 背景

当前前端仅有 Vue Web 端。v1 目标含桌面端（Tauri，可直接复用 Vue 工程）与安卓端（Flutter，独立工程），三端共用同一套 HTTP + WS 接口。本任务为 v1 收尾里程碑，体量最大，建议在后端 API + WS 协议冻结后批量对接。

## 已敲定的共享口径

- **三端功能完全一致**：Web 端有的功能，桌面端与安卓端 v1 全部对齐，不裁剪。安卓端需承担 WebRTC/E2EE/搜索/转发等全部能力的 Flutter 实现。
- **技术栈**：
  - 桌面端：Tauri 直接包装现有 Vue3+Vite SPA，不重写 UI（已确认 Vue 工程为标准 Vite 应用，Tauri 可直接嵌入）。
  - 安卓端：Flutter 独立工程。
- **协议**：三端共用后端 HTTP(8080 `/api/v1`) + WS(8081 `/api/v1/chat`)，WS 协议 `{type, message}`，与 Web 端一致；新增协议字段登记到 v1 协议清单。
- **iOS 不在 v1 范围**。

## 共享需求（约束两个孙任务的共同口径）

- 三端协议实现一致，WS 消息类型、ACK/已读、心跳/重连、多端登录、presence、离线推送等行为与 Web 端对齐。
- 三端功能集 v1 完全一致：登录-会话-收发消息（文本/图片/文件/语音）、已读回执、消息操作（回复/编辑/撤回/转发/@提及/搜索）、在线状态、多端登录、WebRTC 视频通话、E2EE 私聊加密。
- 三端共用同一套 HTTP + WS 接口，不得为某端定制后端接口（原生能力除外，如推送通道）。
- 本地缓存、token 持久化、更新机制、目标平台/最小版本、原生能力清单在各自孙任务 PRD 中敲定。
- 与既有协议任务的协同边界（通知、保活、推送、WebRTC、E2EE 密钥存储）在各自孙任务 PRD 中列为依赖项，待对应协议任务冻结后回填。

## 父级集成验收标准

跨孙任务的最终集成评审口径：

- [ ] Tauri 桌面端在其目标平台可登录并完成 v1 全功能旅程
- [ ] Flutter 安卓端在其目标设备可登录并完成 v1 全功能旅程
- [ ] 三端协议实现一致，行为与 Web 端对齐（按各协议任务冻结结论）
- [ ] 三端功能集一致（v1 全功能，无裁剪）
- [ ] 三端原生能力（桌面通知/托盘/自启、安卓保活/推送/权限）按各自孙任务结论生效
- [ ] 跨端协同正确：多端共存、消息投递一致性、已读回执同步、presence 聚合
- [ ] 各孙任务自身验收标准全绿，且本父级集成评审通过

## 依赖

- **v1 收尾里程碑**：建议在后端 API + WS 协议冻结后批量对接；当前所有 v1 协议任务仍处 planning，协议未冻结。
- 依赖 [[v1-ws-heartbeat-reconnect]]、[[v1-message-ack-read]]、[[v1-redis-stream-consumer-group]] 等地基任务完成。
- 与 [[v1-multi-device-login]]、[[v1-user-presence]]、[[v1-offline-push]]、[[v1-webrtc-video-call]]、[[v1-e2ee]] 协同。
- 依赖协议的细节（通知/保活/推送/WebRTC/E2EE 密钥存储）由各孙任务 PRD 逐项声明，不在此处臆造。
