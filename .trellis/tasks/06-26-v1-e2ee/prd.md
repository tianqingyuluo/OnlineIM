# v1 - 端到端加密（E2EE，私聊可选）

## 背景

私聊消息当前在服务端明文存储（MongoDB）。对于敏感对话，用户希望只有收发双方能解密，服务端无法读取。本任务为私聊提供**可选**的端到端加密。v1 采用 Web Crypto 的静态 ECDH P-256 + HKDF-SHA256 + AES-256-GCM（每条消息独立 salt / IV / 临时公钥），不是完整的 Signal / X3DH / 双棘轮。群聊不在范围内。

## 用户旅程

1. 用户打开私聊。客户端在 IndexedDB（`onlineim-e2ee`）生成或读取身份密钥（ECDH P-256）和签名密钥（ECDSA P-256），只把公钥、`key_id`、算法和指纹 `PUT /api/v1/e2ee/keys`。私钥不离开本机。
2. 会话头或好友设置里有「开启/关闭端到端加密」。打开前双方都必须已上传公钥。开关成功后，服务端保存会话状态，并向双方在线设备推送 `E2EE_STATE_CHANGED`，对端立刻显示或收起 `🔒 端到端加密已开启`。
3. 开启后，发出的文本和回复在本机加密。线上的 `content` 是含 `ciphertext`、`iv`、`sender_key_id`、`recipient_key_id`、`ephemeral_public_key`、`salt`、`counter`、`version` 的 JSON，并带 `is_encrypted: true`。服务端只存密文；会话预览和引用快照都是 `[加密消息]`。
4. 对端、离线补推和历史消息在展示前于本机解密。气泡和侧栏预览显示明文。本机没有私钥或对端公钥变化导致解密失败时，显示 `🔒 [加密消息 · 当前设备无密钥，请导入密钥恢复]`，并可以打开密钥导入。
5. 用户可以查看双方指纹和 60 位安全码，核对后把对方当前指纹标成「已验证 (Verified)」。对方公钥指纹变化时取消验证并警告。
6. 用户用口令导出私钥备份（PBKDF2-SHA256 + AES-256-GCM），在另一台浏览器或设备导入。导入后当前窗口里的密文重新解密。
7. 已读、送达、撤回照常工作，不碰明文。引用只把消息 ID 交给服务端，明文预览留在本机。编辑加密消息会重新加密，即使后来关掉了开关，也不能把旧密文改成明文上传。转发加密消息会被拦住，并提示到原会话查看。图片、文件、表情仍按原方式发送。
8. 关闭开关后，新的文本恢复明文。已经发出的密文仍是密文，本机继续按信封解密。

## 需求

- 私聊可选开启 E2EE。群聊发送或编辑加密内容会被拒绝。
- 私钥只在客户端。服务端公钥目录与会话开关见 `docs/ws-protocol-registry.md`。
- 加密消息的会话预览为 `[加密消息]`。关键词搜索跳过密文，避免把 base64 当成明文命中。
- 客户端提供开关、锁标、安全码核验、口令备份导入、解密失败兜底。
- ACK、已读、撤回、引用、编辑与加密会话兼容。转发加密消息被拒绝并提示。

## e2e 测试场景

| 旅程 | 场景 | 自动化 |
|------|------|--------|
| 1 | 生成密钥并上传公钥包；指纹与服务端 SHA-256(SPKI) 一致；私钥不出现在请求体 | Vitest 密钥与 store；JUnit `E2eeServiceTest` / `E2eeControllerTest` |
| 2 | 好友私聊可开关；非好友、缺公钥、群 ID 被拒绝；双方收到 `E2EE_STATE_CHANGED` | JUnit `E2eeServiceTest`、`E2eeStateReceiverTest` |
| 3 | 文本加密后服务端只存信封；`last_message` 为 `[加密消息]`；非文本加密被拒绝 | JUnit 预览与发送路径；Vitest encrypt/decrypt |
| 4 | 历史、实时、离线消息在展示前解密；无密钥时显示锁定文案 | Vitest store `decryptForDisplay`；历史 store 在需要时才加载密钥模块 |
| 5 | 安全码与指纹顺序无关且为 60 位；指纹变化取消「已验证」 | Vitest crypto + store |
| 6 | 口令备份可导入；错误口令失败 | Vitest `exportKeyBackup` / `importKeyBackup` |
| 7 | 引用快照是 `[加密消息]`；搜索不命中信封；转发加密消息 400；编辑重新加密 | JUnit 回复、搜索、转发、编辑 |
| 8 | 关闭开关后新消息可明文；旧信封仍按密文处理 | 服务端按每条消息的 `is_encrypted` / 信封判断，不按“当前开关”回写历史 |

浏览器里的开关、锁标、核验弹窗和备份弹窗需要登录后的私聊页面。自动化单测覆盖密码学和状态；界面走查依赖可运行的前后端。

## 测试范围

- 后端：`onlineIM-server` 的 `./mvnw test`。覆盖信封识别、预览占位、公钥校验、会话开关与 WS 投递、搜索排除、转发拒绝、引用占位。
- 前端：`npm run test:unit`（Vitest）。覆盖 ECDH 派生、AES-GCM 加解密、备份导入、指纹、安全码、store 的开关 / 锁定 / 核验。
- 类型与构建：`npx vue-tsc --noEmit`、`npm run build`。
- 不在本任务自动化里的部分：Tauri / Flutter 客户端实现（协议已对齐）、完整 Signal 棘轮、群聊加密、媒体内容加密。

## 验收标准

- [x] 私聊可开启 E2EE，服务端不可解密
- [x] 密钥分发与轮换正确（公钥目录、指纹校验、指纹变化警告；v1 为静态 ECDH，不是双棘轮）
- [x] 加密会话内消息可正常收发与解密
- [x] 与既有能力的兼容边界明确并告知用户（预览/搜索/转发/引用/编辑/撤回）
- [x] 协议字段登记到 v1 协议清单
- [x] 单元/集成测试全绿（JUnit + Vitest + vue-tsc + build）

## 依赖

- 与消息回执、引用、编辑、搜索、转发、多端登录协同：回执和撤回不读正文；引用和预览用 `[加密消息]`；搜索跳过密文；转发拒绝；编辑重新加密。
- 群聊 v1 不做 E2EE，仅私聊。
- 多端恢复靠口令备份，不在服务端保存私钥。
