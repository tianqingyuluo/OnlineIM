# v1 - 消息搜索

## 背景

用户需要按关键字搜索历史消息（"我记得谁说过 XX"）。当前消息存 MongoDB，无全文检索入口，用户只能翻记录。本任务提供消息搜索能力。

## 用户旅程

> 原 PRD 此节为待头脑风暴的占位符。2026-10-22 按 tianqingyuluo 给出的 Step 8 要求（按关键字在单个会话内与全部会话中搜索、只搜自己能看到的消息、遵守每人独立的会话记录、排除撤回、编辑过的按当前内容、分页、高亮片段、点击结果跳到该消息并高亮且必要时加载上下文、桌面与手机、Mongo 正则需转义并正确处理中文）补全如下，作为 v1 范围。对头脑风暴各方向的结论：
> - 搜索范围：全局（会话列表里能看到的私聊与所在群）+ 会话内（指定一个会话）；不提供任意会话集合。
> - 搜索对象：只搜文本消息的当前内容；图片 OCR / 文件名 / 语音转写 / 表情 / 聊天记录本期不搜。
> - 结果呈现：按时间流水（倒序），每条显示所属会话（全局）、发送者、时间与命中片段，命中词高亮；不按会话分组。
> - 跳转：点击结果打开所属会话并滚动到该消息、高亮 3 秒；不在已加载列表时先查本地缓存，再用上下文接口加载前后各 20 条。
> - 分页：游标分页，默认每页 20 条、最多 50 条，“加载更多”；关键字 1~50 个字。
> - 检索方案：MongoDB“范围索引 + 字面量正则”（关键字转义，忽略大小写的子串匹配，中文无需分词）；不用 text index（中文不分词效果差），不引入 ES。
> - 权限：与历史记录接口一致。删除（隐藏）的会话不出现在全局搜索里，但打开后可在会话内搜索；退群 / 被移出后搜不到该群；群成员可以搜到入群前的消息（与历史记录一致，新成员本来就能翻看入群前的记录）。

1. 用户 A 在会话列表顶部的搜索框（“搜索会话或聊天记录”）输入关键字，比如“爬山”。
2. 列表先按名称过滤会话；停止输入 300ms 后，下方“聊天记录”列出 A 能看到的会话里内容包含“爬山”的文本消息，最新的在前；每条显示所属会话（群显示“群名 · 发送者”）、时间和命中片段，“爬山”高亮。
3. 结果只包含 A 自己的私聊和 A 所在的群：别人之间的私聊、A 不在的群、A 删除的会话、已撤回的消息、图片 / 文件等非文本消息都不会出现；编辑过的消息按编辑后的内容匹配，原文搜不到。关键字里的 `.`、`*`、`(`、`$` 等按字面匹配，英文不区分大小写。
4. 结果较多时点“加载更多”继续翻页；没有命中时显示“没有找到相关聊天记录”；清空搜索框恢复会话列表。
5. A 点击一条结果：打开所属会话，自动滚动到这条消息并高亮。如果这条消息很早、不在首屏，会自动加载它前后的消息再定位；如果已经打开着这个会话，直接滚动定位。侧栏的搜索结果保留，可以继续点下一条。
6. 在聊天窗口里，A 点右上角的放大镜打开“会话内搜索”面板，输入关键字只搜当前会话（结果显示发送者，自己显示“我”）；点击结果关闭面板并跳到该消息；Esc 或 ✕ 关闭面板，再次打开保留上次的关键字和结果。
7. 新收到 / 刚发出的消息可以立即搜到。
8. 手机上同样可用：会话列表的搜索框进行全局搜索，点结果进入会话并定位；聊天页的放大镜打开占满屏幕宽度的会话内搜索面板。
9. 被拒绝的情况：关键字为空或超过 50 个字、分页游标错误时提示原因；指定了自己无权访问的会话（不是参与者 / 不是群成员 / 已退群）返回 403；跳转时消息已不可用提示“该消息已不可用”。

## 需求

- 新增消息搜索接口 `GET /api/v1/messages/search?q=&conversation_id=&cursor=&size=`。
- 检索范围：全局（会话列表可见的私聊 + 所在群）/ 会话内；对象：文本消息当前内容，排除撤回；v1 方案：范围索引 `{conversationId|groupId, messageType, timestamp, _id}` + 转义后的不区分大小写正则。
- 结果含命中消息 + 所属会话 + 定位信息（seq/messageId）。
- 客户端：搜索入口、结果列表、命中高亮、点击跳转定位。

## e2e 测试场景

> 原为占位符，按上方用户旅程补写（2026-10-22）。自动化脚本：`test/e2e-test.mjs --search`（== 18 节，可单独运行）与 `test/ui-step8.mjs`（真实浏览器，桌面 + 手机）。

- **S1 全局搜索（旅程 1~3）**：S1 搜“爬山”只返回自己私聊与所在群的文本，按时间倒序；结果带 `conversation`（私聊为对方昵称 / 备注，群为群名）、`snippet` 与指向关键字的 `highlights`；`message` 与历史接口格式一致；关键字去首尾空白。
- **S2 访问控制（旅程 3、9）**：搜不到别人之间的私聊、自己不在的群、已撤回与图片消息；同一关键字 S2 能搜到两个私聊与两个群、S3 能搜到自己参与的私聊；`conversation_id` 指定别人之间的私聊 / 不在的群 / 不存在的会话 -> 403。
- **S3 编辑与字面量（旅程 3）**：编辑后的内容可搜、原文不可搜；`(含税)$5.00?`、`a+b` 字面量命中，`.*` 不匹配全部；`onlineim` 命中 `OnlineIM` 并按原文大小写高亮；长消息片段截取命中附近、首尾带“…”；一条消息多处命中都给出位置。
- **S4 会话内搜索（旅程 6）**：`conversation_id` 为私聊 / 群时只返回该会话的命中。
- **S5 分页与校验（旅程 4、9）**：size=5 游标翻页 3 页共 12 条（跨私聊与群），无重复无遗漏，`has_more` 与 `next_cursor` 一致；size 上限 50、默认 20；空 / 缺少 / 超过 50 字的关键字与非法游标 -> 400，50 字可以；未登录 401。
- **S6 入群 / 退群 / 删除会话（旅程 3、9）**：新成员能搜到入群前的群消息、看不到别人的私聊；退群后全局搜不到、会话内 403；删除会话后全局搜不到但会话内仍可搜，对方不受影响，对方再发消息会话重新出现后又能全局搜到。
- **S7 索引**：Mongo 有 `idx_search_conversation_type_time_id` / `idx_search_group_type_time_id`；会话内搜索的查询计划走该索引且无内存排序。
- **U1 桌面 UI（旅程 1~7）**：侧栏搜索列出 2 条命中（别人的私聊 / 不在的群 / 撤回的不出现）、会话名与发送者、高亮；点击不在首屏的私聊结果 -> 打开会话、加载上下文、滚动到可见区域并高亮，`?msg=` 被去掉；点击群结果同理；在同一会话再次点击直接定位；无结果提示、清空后结果消失；放大镜面板获得焦点、只搜本会话、加载更多到 45 条无重复、点结果关闭面板并跳到最早一条、重新打开保留关键字、Esc 关闭；新消息立即可搜。
- **U2 手机 UI（旅程 8）**：全局搜索 3 条（看不到 A–B 私聊）、不超出屏幕、点结果进入私聊并高亮；群聊会话内搜索面板占满宽度、只有本群命中、点结果关闭面板并高亮。
