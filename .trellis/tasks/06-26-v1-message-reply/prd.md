# v1 - 消息回复（引用回复）

## 目标

为私聊和群聊提供引用回复能力，使用户能够明确指出自己正在回应哪一条历史消息，并能够从引用气泡返回原消息上下文。

## 用户价值

- 降低多人群聊和连续对话中的上下文歧义。
- 让文本、图片、文件、语音等消息都可以被明确回应。
- 在历史消息较多时，通过引用跳转快速恢复上下文。

## 仓库确认事实

1. 私聊消息存储在 MongoDB `private_messages`，群聊消息存储在 `group_messages`；两个消息文档目前都没有引用关系或引用预览字段。
2. HTTP 发送 DTO `MessageSendRequest` 已存在未被发送链路使用的 `quoteMessageId` 字段；WebSocket 私聊和群聊发送请求目前没有引用字段。
3. 服务端统一响应 `MessageResponse`、前端 `MessageResponse` 类型以及 IndexedDB 消息缓存目前都没有引用字段。
4. 私聊和群聊消息列表节点已经使用 `message_id` 标识，并支持按 `seq_id` 排序和向前分页加载，为点击引用后定位原消息提供了基础。
5. 服务端当前通过 `status = 3` 表达消息已撤回；消息编辑功能尚未实现，因此引用与编辑的联动契约需要与后续 `v1-message-edit` 任务保持兼容。
6. 消息 ACK、送达/已读回执、心跳重连和 Redis Stream 多实例消费基础已经完成；本任务可以在现有可靠发送链路上扩展消息协议。
7. 当前历史接口只能按 `seq_id` 向前分页，缺少按消息 ID 获取目标消息上下文的接口。

## 范围

### 包含范围

- 私聊与群聊引用回复。
- WebSocket 与 HTTP 发送入口的统一引用协议。
- MongoDB 持久化、Redis Stream 实时投递、历史分页、增量同步及 IndexedDB 缓存中的引用数据。
- Web 客户端的回复入口、发送前引用条、消息内引用气泡、跨分页定位和高亮。
- 原消息撤回、不可用及未来编辑后的引用状态契约。
- 引用目标合法性校验、结构化错误和失败恢复。
- 协议文档、单元测试、集成测试、UI 测试和核心用户旅程 e2e 测试。

### 不包含范围

- 跨会话引用或转发式引用。
- 多层递归展开、主题帖或线程视图。
- 图片/文件实际缩略图；本任务只显示文本占位，缩略图由 `v1-file-image-thumbnail` 完成。
- 消息编辑功能本身；本任务只冻结并预留编辑后的引用状态契约。
- Tauri、Flutter 客户端实现；它们在对应客户端任务中按本任务协议接入。
- 回复数量统计、回复列表聚合和“查看全部回复”。

## 已确认产品决策

### 引用快照与原消息状态联动

- 引用消息保存原消息 ID、序列号、原发送者、消息类型以及发送回复时的简短预览快照。
- 原消息被编辑后，引用气泡继续展示发送回复时的快照，并标注“原消息已编辑”；点击引用定位到最新版原消息。
- 原消息被撤回后，引用气泡不再展示旧内容，改为“原消息已撤回”。
- 原消息被删除或当前用户不再有权访问时，引用气泡显示“原消息不可用”，不展示旧内容。
- 原消息尚未加载或客户端离线时，引用气泡依靠服务端生成的快照正常展示。

### 引用层级

- 允许回复一条本身已经引用其他消息的消息。
- 每条回复只保存并展示当前选中消息的直接引用，不递归复制或展开更早的引用链。
- 点击引用气泡只定位到直接被引用的消息；用户可从该消息继续点击其引用，逐级返回上下文。
- 服务端禁止消息自引用，并保证引用关系不会产生循环。

### Web 端回复交互

- 鼠标悬停消息气泡时显示“回复”快捷图标。
- 右键消息气泡时可从统一消息操作菜单选择“回复”，并为后续编辑、转发和撤回复用该菜单。
- 选中回复后，在输入框上方显示引用条，包含原发送者名称、内容摘要和关闭按钮。
- 按 `Esc`、点击关闭按钮或切换会话时取消当前回复。
- 发送成功后清除引用条；发送失败和重试期间保留引用关系。

### 引用预览

- 文本消息合并换行和多余空格，最多展示 80 个字符，超出部分显示省略号。
- 图片显示 `[图片]`；语音或音频显示 `[语音]`；视频显示 `[视频]`；表情或贴纸显示 `[表情]`；未知类型显示 `[消息]`。
- 文件存在可信文件名时显示 `[文件] 文件名`，否则显示 `[文件]`。
- 引用条和引用气泡最多展示两行。
- 本任务不加载媒体缩略图；后续缩略图任务可在不改变引用协议的前提下增强客户端展示。

### 跨分页定位

- 点击引用时先在当前消息列表和 IndexedDB 缓存中查找原消息。
- 已找到时直接滚动定位，并高亮约 2 秒。
- 未找到时调用消息上下文接口，一次获取原消息及其前后少量消息，合并到当前列表后再定位和高亮。
- 原消息已撤回时定位到撤回占位消息。
- 原消息已删除、无权限或不存在时保留当前滚动位置，并提示“原消息不可用”。
- 不采用逐页循环加载的方式查找很久以前的消息。

### 不可用目标与竞态

- 已撤回消息不显示“回复”入口。
- 用户选中原消息后，如果目标在发送前被撤回、删除或变得不可访问，服务端拒绝发送，不落库、不发布 Redis Stream，也不返回成功 ACK。
- 前端提示“原消息已不可用，请取消引用后重新发送”，并保留正文和引用上下文供用户恢复。
- 已经成功发送的历史回复不受影响，继续按“已撤回”或“不可用”状态展示。

## 用户旅程

### J1：私聊引用回复

1. 用户在一条可用的私聊消息上悬停并点击“回复”，或右键选择“回复”。
2. 输入框上方出现引用条，展示原发送者和预览摘要。
3. 用户输入正文并发送；客户端创建带引用信息的本地临时消息。
4. 服务端校验会话归属和目标状态，以权威原消息生成快照，持久化并发布。
5. 发送方收到 ACK，接收方实时看到引用气泡；刷新或重新进入会话后历史记录保持一致。

### J2：群聊与单层引用

1. 用户在群聊中回复一条普通消息或已经带引用的消息。
2. 新消息只展示当前选中消息的一层直接引用，不递归展开更早的引用链。
3. 接收方点击引用气泡定位到直接被引用的消息，可继续点击该消息中的引用逐级返回。

### J3：取消与失败恢复

1. 用户选中回复后，可通过关闭按钮、`Esc` 或切换会话取消。
2. 用户发送后若网络超时，失败消息和重试数据保留引用信息。
3. 若目标在发送前变得不可用，服务端返回结构化错误；前端不丢失正文和引用上下文，允许用户取消引用后重新发送。

### J4：跨分页定位

1. 用户点击一条引用气泡。
2. 客户端先检查当前内存消息和 IndexedDB。
3. 若目标未加载，客户端只发起一次上下文请求，合并返回的窗口消息。
4. 客户端滚动到原消息并高亮约 2 秒；若目标不可用则保持原滚动位置并提示用户。

### J5：原消息状态变化

1. 原消息编辑后，引用保留发送时快照并显示“原消息已编辑”。
2. 原消息撤回后，引用隐藏旧预览并显示“原消息已撤回”。
3. 原消息删除或不可访问后，引用隐藏旧预览并显示“原消息不可用”。
4. 实时事件、重新加载历史记录和离线缓存同步后的展示结果一致。

## 功能要求

- 发送请求只携带被引用消息 ID，不接受客户端提交的权威引用快照。
- 服务端统一生成快照，并校验目标存在、同会话、当前用户有权访问且目标未撤回。
- 引用快照只包含直接被引用消息自身的摘要，不递归包含该消息已有的引用快照。
- 引用关系不得改变现有 `client_message_id` 幂等、ACK、送达和已读状态规则。
- 引用字段均可空；历史旧消息无需数据迁移即可正常读取。
- 前端本地临时消息、失败重试和离线出站队列必须保留被引用消息 ID 与本地预览。
- 原消息撤回或不可用后，不得通过服务端响应或客户端缓存继续展示旧引用正文。
- 消息上下文接口必须校验会话成员身份，并限制窗口大小。

## e2e 测试场景

- [x] E1（映射 J1）：两名用户完成私聊引用回复，验证本地临时态、ACK、实时接收和刷新后的历史一致性。
- [x] E2（映射 J2）：群成员回复一条引用消息，验证只展示一层并可逐级点击定位。
- [x] E3（映射 J3）：选择目标后目标被撤回，再发送回复；验证无落库、无 Redis 发布、无成功 ACK，正文和引用上下文可恢复。
- [x] E4（映射 J4）：目标消息不在当前分页和内存中但存在于服务端，验证一次上下文请求、消息合并、滚动和高亮。
- [x] E5（映射 J4/J5）：目标不存在或无权限，验证滚动位置不变并显示“原消息不可用”。
- [x] E6（映射 J5）：原消息撤回后，实时客户端和重新加载历史的客户端均不再看到旧引用正文。
- [x] E7：断线重连或失败重试后，引用消息仍按相同 `client_message_id` 幂等，不重复落库。

## 依赖与协同

- 与 `v1-message-edit` 协同使用内容版本判断编辑状态。
- 与 `v1-recall-time-window` 协同定义撤回事件和状态。
- 与 `v1-emoji-system`、`v1-voice-message`、`v1-file-image-thumbnail` 协同扩展非文本消息预览。
- Tauri 和 Flutter 客户端在对应任务中按照本任务冻结的协议实现。
