# v1 - 草稿同步

## 背景

用户在 A 端输入框写了一半消息，切到 B 端时希望看到同样的草稿继续发。当前输入只留在打开着的页面里，刷新或换设备就没了。本任务把每个用户、每个会话的一份未发送草稿存到服务端。

2026-10-21 按本次任务给定的结果补全用户旅程（不再单独做一轮问答）。结论：

- 同步时机：输入停止约 0.5 秒后保存；发送或清空时立即删除。切换会话、离开页面时把还没到点的内容补写一次。
- 内容：只保存文本，以及这份文本上的回复目标和群 @（成员 id + 插入时的显示名）。图片 / 文件 / 语音 / 表情的选择不进草稿。
- 冲突：后写覆盖。本地还有没保存的更新输入时，不拿其他设备的推送覆盖输入框；列表摘要仍会更新，随后以最后一次成功保存为准。
- 生命周期：发送或内容变成空白就删除。不设条数上限（每会话一份），正文最长 5000 字符。
- 粒度：每个用户每个会话一份。
- 与编辑：进入“编辑消息”前先把草稿（含回复目标，群聊含 @）提交并在本地暂存；编辑过程中的原文不写入草稿。保存或取消后恢复。切换会话时丢掉编辑态，服务端仍是编辑前那份草稿。

## 用户旅程

1. 用户 A 在私聊或群聊输入框里打字，停大约半秒。草稿按“用户 + 会话”存到服务端。群聊里通过 @ 选择器选中的成员、以及正在回复的那条消息，和文本一起保存。
2. A 关掉页面或换一台设备，打开同一个会话：输入框恢复那段文字；有回复时回复条也在；群聊里原来 @ 的人仍然算选中。会话列表（桌面侧栏和手机列表）在最后一条消息的位置显示红色 `[草稿]` 加摘要，例如 `[草稿] 写了一半`。若这条会话还有未读的 `@我`，`[有人@我]` 留在 `[草稿]` 前面。
3. 另一台已经打开的设备：收到 `DRAFT_UPDATED` 后，列表摘要立刻更新；如果那个会话开着、而且本地没有更新的未保存输入，输入框也换成新草稿。本地正在打字时不被盖掉。切回浏览器标签或刷新页面会再拉一次。
4. A 把消息发出去，或把输入框删空：这份草稿从服务端消失，列表不再显示 `[草稿]`，其他设备同样清掉。
5. A 在已有草稿时点“编辑”自己的一条文本：原文进入输入框，原来的草稿（含回复条和 @）先存好并暂存。编辑期间不把原文当成新草稿。保存或取消（Esc / ✕）后，输入框、回复条和 @ 回到编辑前。改会话时直接退出编辑，不把编辑内容带到下一个会话。
6. 两台设备同时改同一会话：后保存成功的那份留下。引用的消息已经撤回或不存在时，文本仍然保存，引用被丢掉。不是群成员的 @、@ 自己、私聊里的 @ 都不会存。已退群、或私聊里既没有会话记录也已经不是好友时，保存被拒绝。

## 需求

- MongoDB `conversation_drafts`：每个用户每个会话一份（`_id = userId:conversationId`），后写覆盖。
- `GET/PUT/DELETE /api/v1/conversations/{conversationId}/draft`。空白内容即删除。
- 会话列表和详情带 `draft_preview`。保存 / 删除后给草稿主人推 `DRAFT_UPDATED`。
- 客户端：防抖保存、打开会话和刷新后恢复、列表 `[草稿]`、发送或清空后删除。编辑消息时暂存草稿，不把编辑内容写入草稿。桌面和手机共用会话行和输入框。

## e2e 测试场景

本次没有新增需要真实浏览器或 Docker 的自动化脚本（由仓库主人在真实 Docker 栈上手工验证，见 PR 说明）。下面的场景由单元测试覆盖对应行为，手工步骤见 PR。

- **E1 保存与恢复（旅程 1、2）**：成员 `PUT` 带文本、回复 id、群 @ → 200，摘要折叠空白；`GET` 得到同样的文本、回复快照和仍在群里的 @。会话列表 `draft_preview` 为摘要。非成员 403，超长 400，未登录 401。
- **E2 引用不可用（旅程 6）**：回复目标不存在或已撤回 → 文本仍保存，`reply_to` 为空。
- **E3 后写覆盖与去重（旅程 3、6）**：第二次不同内容覆盖第一次；内容、引用和 @ 都没变则不写库、不推送。
- **E4 清除（旅程 4）**：空白 `PUT` 或 `DELETE` 删掉草稿并推 `cleared: true`；本来就没有则不推送。
- **E5 多端帧（旅程 3）**：`DRAFT_UPDATED` 只发给草稿主人，并扇出到本节点上该用户的每条连接，帧体带 `conversation_id` 和内容。
- **U1 输入框（旅程 1、4、5）**：停止输入 500ms 后 `PUT`；清空后 `DELETE`；打开会话 `GET` 并填回文本、回复和 @。编辑期间不上传编辑原文，取消后草稿还在。本地有未保存文字时，远程推送只改列表、不改输入框。
- **U2 列表（旅程 2）**：有 `draft_preview` 时显示 `[草稿]` 加摘要，不再显示最后一条消息；同时 `at_me` 时 `[有人@我]` 仍在。桌面侧栏和手机列表用同一个组件。

## 测试范围

- **后端单元**：`DraftPreviewTest`（空白折叠、按 code point 截断）；`DraftServiceTest`（保存并推送、引用不可用仍保存文本、空白删除、相同内容不重写、后写覆盖、非成员 / 超长、好友无记录也可存、群 @ 清洗、私聊忽略 @、列表摘要、推送失败不回滚）；`DraftUpdatedReceiverTest`（推给本人的每条连接、本节点不在线则跳过）；`ConversationDraftControllerTest`（snake_case、用登录用户）；`ConversationServiceImplTest`（列表带上 `draft_preview`）；`ConversationIdUtilTest`（从私聊 id 解析对方）。
- **前端单元（vitest）**：`draft` 摘要与签名；`useConversationDraft`（恢复、防抖保存、清空删除、编辑态不上传、脏输入不被远程覆盖、干净时应用远程草稿并更新列表）；`conversation.service` 的三个草稿路径；`websocket` 把 `DRAFT_UPDATED` 交给草稿总线；会话列表 `[草稿]` / `[有人@我]`；`useMessageEdit` 暂存并恢复回复目标。
- **手工**：见 PR 描述。不在本环境起 Docker 全栈。
