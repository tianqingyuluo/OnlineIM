# v1 - Redis Stream 消费者组多实例去重

## 背景

跨实例消息转发当前用 Redis Stream（`im:message:stream`）。`RedisEventListener` 实现 `StreamListener`，但启动流程里**未见消费者组（consumer group）注册与 `XREADGROUP` 配置**。若多实例都从 `$`/`0` 读全量流，同一消息会被每个实例消费 → 在线用户收到重复消息。这是横向扩展的正确性 bug，不是功能增强。

## 用户旅程

> ⚠️ **占位符 —— 待头脑风暴**
>
> 本任务的执行模型在启动前，**必须先与用户（tianqingyuluo）进行用户旅程的头脑风暴问答**：虽为后端正确性任务，仍需明确"多实例下消息分发"在用户视角的行为预期与边界。
>
> 头脑风暴建议覆盖的方向（仅供启发性参阅，最终以问答结论为准）：
> - 多实例规模预期（2？N？）是否影响 group 设计？
> - receiver 在线判定口径：仅本地在线 vs 跨实例可见性来源？
> - 不在本实例的消息"跳过 ack"还是"转发兜底"？
> - 实例崩溃恢复时 PEL 的处理粒度与可见性？
> - 全员离线时消息的生命周期与上限？
>
> 待用户旅程确定后，在此记录编号的端到端步骤，**随后再据此编写下方 e2e 测试**。在此之前 e2e 测试场景保持占位，不得臆造。

## 需求

- 启动时创建 consumer group（`XGROUP CREATE ... MKSTREAM`，已存在则忽略 BUSYGROUP）。
- 消费改用 `XREADGROUP`，consumerId = serverId。
- 消费侧：receiver 在本实例在线则投递并 `XACK`；不在则按头脑风暴结论决定跳过 ack 或转发兜底。
- 实例宕机恢复处理 PEL，避免丢消息。
- 在 `WebSocketConfig`/新增配置中声明 `StreamMessageListenerContainer` + group。
