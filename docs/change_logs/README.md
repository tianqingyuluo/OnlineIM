# Change Logs 维护规范

本目录 `docs/change_logs/` 用于记录项目开发过程中的所有变更。**所有记录必须使用中文。**

## 记录类型与触发时机

### 1. 变更日志（change-log）

**触发时机**：每次代码变更后（新增、修改、删除文件）。

**文件命名**：`YYYY-MM-DD-<简短英文描述>.md`

**内容要求**：
- 日期
- 变更摘要：新增/修改/删除了哪些文件，每项变更的原因
- 关联任务（如有 Trellis 任务，附 task slug）

### 2. 任务完成记录（task-summary）

**触发时机**：Trellis 任务完成（`task.py finish` / archive）时。

**文件命名**：`YYYY-MM-DD-task-<task-slug>.md`

**内容要求**：
- 任务 ID（slug）与标题
- 变更范围：影响的模块、文件列表
- 验收结果：是否通过 lint / typecheck / 测试
- 遗留问题（如有）

### 3. 技术方案变更记录（tech-design-change）

**触发时机**：技术设计方案发生变更时（架构调整、技术选型变更、接口契约修改、数据模型变更）。

**文件命名**：`YYYY-MM-DD-tech-<简短英文描述>.md`

**内容要求**：
- 变更背景：为什么需要变更
- 方案对比与决策：考虑了哪些方案，为什么选当前方案
- 影响评估：对现有系统、模块、接口的影响
- 关联任务（如有）

## 格式约定

- 所有文件使用 Markdown 格式
- 文件名使用日期前缀，描述部分用英文短横线连接（例如 `2026-06-26-add-ws-heartbeat.md`）
- 正文内容全部使用中文
- 每条记录应独立可读，不依赖其他文件即可理解变更内容
