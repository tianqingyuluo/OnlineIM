# WebSocket 重连与端点契约补充

## 变更背景

WebSocket 心跳与重连收尾检查发现两个容易被忽略的边界问题：旧连接迟到事件可能干扰新连接状态，以及服务端虽然配置了 WebSocket 路径但未实际限制升级路径。两者都可能造成难以复现的连接异常或暴露非预期端点。

## 方案对比与决策

- 旧连接事件处理：相比依赖全局 `this.ws` 状态，选择让每组事件处理器捕获创建时的 socket，并在回调入口校验它仍是当前连接。该方案不需要额外连接编号，且能直接隔离旧连接事件。
- WebSocket 路径限制：相比为每条路径创建额外 Router upgrade 路由，选择在全局 `webSocketHandler` 入口提取 URI path 并与 `websocket.path` 精确比较。实现简单，同时保留现有认证和会话创建链路。
- 验证方式：新增真实 Vert.x 服务端与客户端集成测试，mock JWT 和 Redis 边界，验证真实升级、文本帧、关闭事件和路径拒绝。

## 影响评估

- 前端重连状态机不再受旧连接迟到事件影响，离线队列的消息确认 ID 可以稳定贯穿重连发送与服务端响应。
- 后端只接受配置路径上的 WebSocket 升级；此前通过其他路径建立连接的非标准客户端将收到 404，需要改用 `websocket.path` 指定的路径。
- 不修改现有 `HEARTBEAT` / `HEARTBEAT_ACK` 帧结构和业务消息协议。
